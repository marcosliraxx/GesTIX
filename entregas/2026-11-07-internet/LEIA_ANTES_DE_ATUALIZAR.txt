ATUALIZAÇÃO DA ABA INTERNET — AGENTE WINDOWS T.I DIGITAL

1. ATUALIZAR PELO CPANEL
Faça uma cópia dos arquivos que serão substituídos. Envie o ZIP
ATUALIZACAO_INTERNET_CPANEL.zip à raiz do sistema (a pasta que contém index.php,
api e agentes) e extraia, permitindo substituir os arquivos existentes.
As pastas api e agentes do ZIP devem se mesclar às pastas atuais.
Não extraia dentro de api nem dentro de agentes.

O ZIP contém somente as alterações, com os caminhos corretos:
- api/download-agent.php
- agentes/servidor/Arcoll.WinUI3/Pages/SpeedPage.cs
- agentes/servidor/Arcoll.WinUI3/Assets/hybrid/internet/index.html
- agentes/servidor/Arcoll.WinUI3/Assets/hybrid/internet/styles.css
- agentes/servidor/Arcoll.WinUI3/Assets/hybrid/internet/app.js
- agentes/servidor/Arcoll.WinUI3/Assets/hybrid/internet/vendor/leaflet.js
- agentes/servidor/Arcoll.WinUI3/Assets/hybrid/internet/vendor/leaflet.css

2. ATUALIZAR O APLICATIVO WINDOWS
A tela do print é de um executável WinUI 3. Subir os fontes ao cPanel atualiza
o pacote de fontes disponibilizado pela plataforma, mas não modifica os
executáveis já instalados nem gera uma release pré-compilada.

Após o upload, use o fluxo existente de compilação/instalação do agente em
Windows para obter os novos fontes e gerar o aplicativo. Os scripts existentes
Compilar-WinUI3.ps1 e INSTALAR_WINUI3.ps1 continuam disponíveis no sistema.
Teste o agente gerado em um computador antes de distribuir aos demais.

Se usa distribuição PRÉ-COMPILADA: em uma cópia completa do sistema com os
arquivos deste pacote aplicados e SDK .NET 8/ferramentas Windows instalados,
execute no PowerShell:

cd agentes\servidor\Arcoll.WinUI3
.\PUBLICAR_RELEASE_PRECOMPILADA.ps1 -Arch win-x64

O script já existente informa a pasta de saída. Envie o CONTEÚDO da pasta
current gerada para agentes/releases/win-x64/current no servidor, incluindo
release.json e files, preservando uma cópia da release anterior. Para ARM64,
repita com -Arch win-arm64 e publique na pasta dessa arquitetura.
Use o controle central de versões do sistema para identificar a nova release.
Não apague configurações locais nem agent-config.json.

3. CONFERÊNCIA
Abra Internet no agente atualizado. Execute um teste e confira download,
upload, latência, perdas, jitter e latências sob carga. Compare os resultados
sincronizados na plataforma. O mapa prioriza os pontos confirmados na
plataforma; na ausência deles usa a localização aproximada da provedora e o
endereço estimado, quando disponíveis. Sem coordenadas suficientes a interface
avisa em vez de inventar uma ligação. Os saltos continuam em uma seção própria.

O mapa-base usa https://tile.openstreetmap.org e requer acesso à internet.
A biblioteca Leaflet acompanha o pacote localmente. O núcleo de medição e a
sincronização permanecem os mesmos. Caso WebView2 não inicialize, a tela nativa
anterior permanece como alternativa.

4. VALIDAÇÃO REALIZADA
JavaScript validado com node --check. Interface testada no Chromium com
Playwright: indicadores, botão/ponte de mensagens, bloqueio durante medição,
layout estreito sem rolagem horizontal, valores ausentes, texto seguro e tema
escuro. Recursos conferidos contra a lista de distribuição do PHP.
A prévia usa dados de exemplo; não é uma medição real.
Neste ambiente o mapa-base externo não carregou; marcadores, ligação e aviso
de indisponibilidade funcionaram. Não foi possível compilar/executar WinUI 3
nem realizar o teste de velocidade Windows neste ambiente Linux. PHP CLI
não está instalado para executar php -l. A validação final em Windows é necessária.

5. VOLTAR À VERSÃO ANTERIOR
Restaure api/download-agent.php e SpeedPage.cs das cópias anteriores. A pasta
Assets/hybrid/internet pode ser removida após a reversão. Para aplicativos já
atualizados, reinstale ou republique a release anterior usando o fluxo existente.
